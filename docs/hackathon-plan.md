## 1. 대회 이해 (안내자료 2·15·16쪽)

- **형식**: 1박 2일. 마산대(보건) + 연암공대(공학) 학생이 한 팀이 되어 헬스케어 현장 문제 하나를 골라 AI 해결 아이디어를 기획하고 작동하는 형태로 보여 줍니다. 정답은 없고, **"문제를 겪는 사람을 얼마나 깊이 이해했는지, 그 이해가 아이디어에 어떻게 담겼는지"**가 핵심입니다.
- **1일차**: 문제 공감(페르소나·여정맵) → 문제 정의(HMW 질문) → 아이디어와 핵심 기능 → 화면 설계 → 야간 프로토타입·발표 준비 → 중간 피칭 피드백
- **2일차**: 발표 자료 완성 → 멘토링 → 최종 발표·시상
- **제출물 3종**
  1. 실습 워크북 — 페르소나 · 여정맵 · HMW · 핵심 기능 · 화면 스케치 (이 문서)
  2. 핵심 기능이 작동하는 **웹앱 시연 화면 또는 시연 영상**
  3. **10장 발표 자료** (문제 → 해결 → 시연 → 효과)
- **평가(안) 100점**: 문제정의 및 공감 20 · 솔루션 창의성 20 · 산출물 완성도 20 · 기대효과 및 사업화 20 · 융합 협업 및 발표 20
- **발표 형식**: 팀 발표 10분 + 질의응답 3분 · PPT 15장 이내 (10장 구성안은 11장)
- **일정·장소·팀 배정**: `[확인 필요 — 학교 공지 확인]`

> 평가표를 그대로 작업 순서로 바꾸면 이렇게 됩니다.
> **문제정의(20)** = 3·4·5장 → **창의성(20)** = 6장 → **완성도(20)** = 7·8장과 실제 시연 → **기대효과(20)** = 11장 9~10쪽 → **협업·발표(20)** = 10·11장.

## 2. 주제 선택과 근거

### 2-1. 왜 01·08·10을 합쳤나

| 후보 주제 | 다온이 이미 가진 것 | 판단 |
| --- | --- | --- |
| 01 여러 병원 약을 함께 드시는 어르신의 복약 안전 | 사진에서 글자 읽기(약봉투·처방전), 맞춤 알림 | **채택** — OCR·알림 자산이 그대로 쓰이고, 보건 전공이 검수할 "문구 안전성"이 핵심 |
| 08 하루 종일 말 한마디 없는 어르신과 멀리 사는 가족 | 웹 음성 통화(안부 전화), 대화 요약 | **채택** — 통화 자산을 그대로 쓰고, "신호 vs 진단" 경계를 보여 주기 좋음 |
| 10 하루 여섯 집을 도는 방문 간호사·요양보호사 | 통화·알림 요약 카드 | **부분 채택** — 기록 전체가 아니라 "통화·복약 결과를 돌봄 인력·보호자에게 넘기는 연결"만 |
| 05 간호사 인수인계, 06 당뇨 식사, 07 재활 자세 | 없음(새로 만들어야 함) | 이번 2일에는 제외 (다음 단계 확장으로 남김) |
| 09 응급 감지(웨어러블) | 없음 | 제외 — 기기·센서 의존, 진단으로 보일 위험 |

- 세 주제 모두 **"정보가 있어도 그 정보를 사람에게 옮겨 주는 사람이 없다"**는 같은 뿌리를 갖습니다. 하나의 제품으로 묶는 것이 팀 2일 안에 완성도 있게 보여 줄 수 있는 유일한 길이라고 판단했습니다.
- 안내자료도 "같은 주제라도 다른 사람(페르소나), 다른 상황을 그리면 전혀 다른 문제가 됩니다. 적극 권장"이라고 안내합니다(15쪽).

### 2-2. 이 제품이 새롭게 하는 것 (기존 앱과 비교)

| 기존 앱 | 부족한 점 | 다온 헬스케어 |
| --- | --- | --- |
| 병원·약국 앱, 복약 알림 앱 | 약 이름을 **사람이 직접 입력**해야 함. 글씨가 작고 메뉴가 복잡 | **약봉투 사진 한 장**으로 약 이름·먹는 법을 읽어 일정을 자동으로 만듦 |
| 건강 상태 앱 | 수치를 보여 줄 뿐 "그래서 뭘 해야 하지"가 없음 | 매일 **말로 안부**를 묻고, 그 답을 요약해 **보호자·돌봄 인력에게 전달** |

## 5. HMW 질문

도출 과정: 여정맵에서 가장 자주 막힌 지점(②③)과 가장 위험한 지점(⑦)을 골라 질문으로 바꿨습니다.

1. **HMW-1** "약봉투 글씨를 읽기 어려운 어르신이, 여러 병원 약을 **빠뜨리지 않고 겹치지 않게** 드시도록 도우려면 어떻게 해야 할까?"
2. **HMW-2** "하루 종일 말이 없는 어르신 곁에서, 기계가 **'계속' 대화하게** 만들어 외로움을 덜고 변화를 가족이 가장 먼저 알게 하려면?"
3. **HMW-3** "방문 돌봄 인력이 기록에 쓰는 시간을 줄이면서, 어르신의 상태 변화를 **끊김 없이** 넘기려면?"

**선정: HMW-1** (2일 안에 작동하는 화면으로 가장 확실히 보여 줄 수 있고, 보건 전공의 검수 역할이 가장 분명해짐)
→ HMW-1에서 **HMW-1'** 로 좁힘: *"약봉투 사진 한 장으로, 오늘 먹을 약과 시간을 대신 정리해 주고, 잊었을 때 사람에게 알려 주려면?"*
(HMW-2·3은 각각 '안부 전화'와 '결과 전달' 기능으로 흡수)

## 6. 핵심 기능 5가지

| # | 기능 | 사용자가 하는 일 | AI가 하는 일 | 보건 전공이 정하는 것 | 화면 |
| --- | --- | --- | --- | --- | --- |
| F1 | **약봉투 읽기** | 봉투를 찍거나 예시로 시연 | 사진에서 약 이름·1회량·횟수·식전/식후·일수를 읽어 일정으로 변환 | 어떤 항목을 읽어야 하는지, 틀렸을 때 어떤 문구로 확인시키는지 | 오늘의 약 → 약봉투 읽기 |
| F2 | **오늘의 복약** | 시간대별 약을 보고 눌러서 체크 | 남은 약·다음 시간 계산, 미복용 시 재알림 | 식전·식후 표기 기준, 재알림 간격, "약을 바꾸지 않는다" 문구 | 오늘의 약 |
| F3 | **안부 전화** | 다온이 거는 전화를 받고 짧게 답함 | 질문 → 답 → 되짚기, 통화를 3줄로 요약 | 질문 순서(복약→식사→수면→통증), 위험 신호일 때 119 안내 | 안부 전화 |
| F4 | **맞춤 알림·연계** | 받을 소식을 켜고 끔 | 복약·병원·방문 돌봄·보호자 공유를 골라 알림 | 알림 문구의 안전성, 알림을 보낼 시점 | 맞춤 알림 |
| F5 | **안전 경계** | 어지럽다·아프다라고 말함 | 판단하지 않고 119·의료진·보호자로 연결 | "무엇을 말하지 않을지"의 목록과 표현 | 채팅 · 119 안내 |

**이번 시연에서 실제로 보여 줄 것(F1~F4는 작동, F5는 대화로 확인)**: 약봉투 읽기 → 일정 자동 생성 → 체크 → 안부 전화 → 요약 전달 → 알림 센터.

## 12. 시연 대본 (3분, 클릭 순서)

1. (0:00) 첫 화면 — "모두 가상 데이터입니다. 실제 환자 정보는 쓰지 않았습니다." → **가상 데이터로 시작하기**
2. (0:15) 채팅 — "안녕하세요, 이순자님" 인사와 **오늘의 복약·돌봄 카드** 소개
3. (0:40) **오늘의 약** 탭 → 약봉투 사진 버튼 → **예시 약봉투로 해 보기** → 읽는 애니메이션 → **결과 확인**(3종 중 2종 새 약, 1종은 이미 복용 중이라 건너뜀) → **오늘 일정에 넣기**
4. (1:30) 체크 버튼으로 아침약 완료 → 진행률이 오르는 것 확인
5. (1:45) **안부 전화** 탭 → **복약 확인 전화** → 다온의 질문에 답변 칩으로 응답 → **정리 카드(DAON-CALL-…)** → **보호자에게 전달**
6. (2:30) **맞춤 알림** 탭 → 알림 센터에 전달 기록, 병원·복지 연계 알림 소개
7. (2:50) 채팅에 **"가슴이 아파요"** 입력 → "119에 전화해 주세요, 다온은 판단하지 않아요" 화면으로 **안전 경계** 마무리

**비상 대본**: 인터넷이 없으면 → 예시 약봉투 경로만 사용(사진 OCR은 생략). 소리가 안 나면 → 자막으로 진행(모든 대사가 화면에 남음). 브라우저가 느리면 → 미리 찍어 둔 시연 영상 재생.
