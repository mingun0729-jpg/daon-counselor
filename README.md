## 2. 장애인 특성을 고려한 화면

- **큰 버튼·넉넉한 여백·짧은 문장**: 한 화면에 핵심 한 가지, 버튼은 56~62px(큰 글씨 모드 64~72px).
- **쉬운 말**: "복지카드 찍기", "할 수 있는 일자리", "나라에서 서류 가져오기", "빠진 것만 적고 내기".
- **편하게 보기 3버튼** (화면 위, 늘 보이는 자리):
  - `글씨 크게` — 본문 20px 이상, 버튼 64px 이상
  - `고대비` — 검은 배경·밝은 글씨로 대비를 높임
  - `읽어주기` — 화면을 한국어 음성으로 읽어 줌 (기본 속도 **0.82 천천히**, 0.93 보통 선택)
- **장애 유형별 자동 배려**: 카드를 읽으면 유형에 맞춰 화면을 맞춥니다.
  - 지체·뇌병변 → 큰 버튼, 짧은 화면
  - 시각 → 큰 글씨 + 읽어주기 자동 켜기
  - 청각 → 모든 안내를 글로 크게
  - 지적·자폐성 → 쉬운 말 모드(짧은 문장, 긴 설명 접기)
  - 정신 → 근무 시간·업무 조정 안내
- 키보드·스크린리더를 위한 `aria-*`, 본문 바로가기, 포커스 표시, 움직임 줄이기 설정 대응.
- 화면을 바꾸면 새 화면 제목으로, 모달을 닫으면 열었던 버튼으로 포커스가 돌아갑니다.

## 3. 시연 방법 (1분)

1. `복지카드 찍기·올리기`로 카드 사진을 고르면 **브라우저 안에서 실제로 글자를 읽어** 성명·생년월일·장애유형·정도·등록일·발급기관을 채우고 확인 화면을 띄웁니다(진행률·취소 버튼 있음). 확인 화면에서 틀린 칸만 고쳐 `이 내용으로 등록`을 누릅니다.
   - 사진을 못 읽으면 "글자를 또렷이 읽지 못했어요" 안내 뒤 `사진 다시 고르기` · `내 정보 직접 입력` · `예시 인물로 계속` 중에서 고릅니다.
   - 카드 없이 보여 주려면 `예시 인물로 해 보기` → **지체장애 · 심한 장애**(김다온, 가명) → `이 예시 정보로 계속`.
2. 예시 카드를 준비하는 4단계 연출 → `카드 정보 확인` → `일자리 조회`
3. 조건에 맞는 일자리와 진주 근무지 확인 → 근무지 카드에서 **1순위·2순위·3순위** 지정(같은 순위를 다시 누르면 해제, 다른 카드의 순위를 누르면 자리 바꿈·교체) → `서류 준비`
4. `기관 로그인 · N장 수집` → 인증 화면
   - **프록시를 연결한 경우**: 성명·생년월일 8자리·휴대폰·통신사·인증수단을 넣고 `인증 요청 · 서류 가져오기` → 휴대폰 앱에서 인증 → 화면의 `인증 완료 확인` → 실제 응답값이 서류 카드·신청서·자격 판정에 반영됩니다(4-2 참고).
   - **연결하지 않은 경우**: "실제 기관 조회를 하려면 프록시 연결이 필요합니다" 안내와 설정 바로가기가 뜨고, 보조 버튼 `시연용 예시 데이터로 미리보기`로만 진행합니다. 시연 인증 방법(카카오·네이버·공동인증서·아이디)을 고르면 "정부24에 접속하고 있어요 → 로그인 완료 → 주민등록등본 서류를 받았어요 → 신청서에 붙였어요" 로그가 차례로 쌓입니다
   - 서류는 실제 파일 카드(파일명·발급기관·크기·`미리보기`·`저장`)로 표시되고 `신청서에 자동 첨부됨` 배지가 붙습니다
5. `신청서 작성` → 맨 위 **내 정보 확인·수정**에서 이름·생년월일·사는 곳·필요 지원·이동 수단과 **희망 근무지 1·2·3순위**를 확인(순위 바꾸기 가능)하고, 아래에서 연락처·계좌 입력, `AI 초안 생성`으로 자기소개 작성, 필요하면 **추가 신청서 항목(선택)**에서 성별·소득수준·최종학력 등을 고릅니다
6. **3. 신청 자격 판정**에서 판정 결과(가능/확인 필요/신청 제한)를 확인합니다. 제한 항목이 있으면 `신청서 제출`이 막히고, 2단계 `신청 자격 확인`에서 항목을 바꾸면 바로 다시 계산됩니다
7. **4. 자필 서명** 칸에 마우스나 손가락으로 이름을 씁니다(`다시 쓰기` · `도장(인)으로 대체` · `이름 입력으로 대체` · `서명 지우기`). 서명하지 않으면 제출되지 않습니다
8. **5. 공식 서식 3종** 탭에서 서식 1·2·3을 넘겨 보고, `3종 모두 인쇄·PDF`로 A4 4쪽을 인쇄하거나 `HTML로 저장`합니다
9. `신청서 제출` → 접수번호가 나오고 인쇄·ZIP 저장·메일 보내기. ZIP에는 **서식 3종 HTML + 요약 JSON + 접수증 + 올린 사진 원본**이 함께 들어갑니다

다른 예시: **청각·언어장애 · 심하지 않은 장애**, **지적장애 · 심한 장애**(쉬운 말 모드), **정신장애 · 심하지 않은 장애**. 예시 인물은 7종입니다.

## 4. 무엇이 시연이고 무엇이 진짜인가

| 구분 | 내용 |
| --- | --- |
| 시연(가상, 기본값) | 기관 로그인 연출, 서류 자동 수집·첨부, 접수, 접수증, 시연용 서류 파일 내용 |
| 실제 작동(프록시 연결 시) | 정부24·국민건강보험공단 **간편인증 실제 조회**(CODEF API): 건강보험 자격득실확인서, 주민등록등본, 장애인증명서. 받은 값(가입자구분·사업장·자격취득·상실일 / 세대주·주소 / 장애유형·정도·등록번호)이 서류 카드·신청서·자격 판정에 그대로 반영 |
| 실제 작동(브라우저 로컬) | 복지카드 사진 글자 판독(OCR) — Tesseract.js(한국어+영어)를 브라우저에서 돌려 성명·주민번호 앞자리(생년월일)·장애유형·정도·등록일·발급기관을 읽고 확인 화면에 채움. 사진 픽셀은 전송하지 않음(내려받는 것은 글자 읽기 엔진뿐) |
| 미지원(안내함) | 인터넷이 없어 OCR 엔진을 못 받는 경우 — 안내 후 직접 입력·예시 인물로 이어짐 |
| 실제 정보 | 접수처 **(사)경남지체장애인연합회 진주시지회**의 기관명·주소·대표전화(055-755-0008) |
| 실제 기준 | 2026년 장애인일자리 사업안내(보건복지부)의 사업 종류·근무시간·보수, 공식 서식 3종의 표 구조·문구·법령(4-1 참고) |
| 실제 작동 | 자격 판정(지침 수치·예외 적용), 자필 서명 캔버스와 서식 반영, 서식 3종 HTML 생성·A4 인쇄, ZIP 묶음(서식 3종 + 요약 JSON + 올린 사진 원본) |
| 가상 값 | 신청인 이름·연락처·주소·계좌·경력 등 모든 개인 정보는 가명·예시 |

- 카드 사진은 **서버로 전송되지 않습니다.** 사진은 브라우저 안에서만 판독되고(글자 읽기 엔진만 CDN에서 내려받음), 읽은 값은 확인 화면에서 사용자가 고칠 수 있습니다. 주민등록번호 뒷자리는 읽어도 저장하지 않고 `810716-1******`처럼 가립니다.
- 기관 로그인은 **프록시를 연결하지 않으면** 실제 아이디·비밀번호를 넣지 않는 원클릭 시연이며 어떤 정보도 외부로 보내지 않습니다(외부 요청 0건).
- 프록시를 연결하면 입력한 **성명·생년월일·휴대폰 번호가 다온 프록시를 거쳐 CODEF·기관으로 전송**됩니다. 다온은 이 값을 저장하지 않고, 화면을 닫으면 사라집니다. 프록시 주소는 브라우저(`daon.codef.v1`)에만 저장됩니다.
- 만들어진 서류 파일은 브라우저 안에서만 생성됩니다. 실제 조회값이 있으면 **"기관 조회 결과(요약)"**으로 표시하고 원본 증명서를 대신하지 않는다고 적으며, 없으면 **가상 문서**입니다. 실제 신청은 협회 담당자 안내에 따라 본인이 서류를 준비·서명해야 합니다.

### 4-2. 실제 기관 조회(CODEF 간편인증) 연결

다온은 GitHub Pages의 정적 페이지라 CODEF 키를 브라우저에 둘 수 없습니다. 그래서 저장소 안에 **바로 배포하는 프록시**(`proxy/cloudflare-worker.js`, Cloudflare Workers)를 함께 두었습니다. 배포·키 설정은 [`proxy/README.md`](proxy/README.md)의 3단계를 따릅니다.

1. CODEF 가입 → MY > 키 관리에서 `clientId`·`clientSecret` 확인
2. `proxy/` 폴더에서 `wrangler secret put` 두 번 + `wrangler deploy`
3. 다온 **서류** 화면 → `⚙️ 기관 API 연결 설정` → Worker 주소 붙여넣고 `연결 테스트` → `저장`

| 다온 서류 | CODEF 상품 | 엔드포인트 |
| --- | --- | --- |
| 건강보험 자격득실확인서 | 민원여기요 자격득실확인 | `/v1/kr/public/pp/nhis-join/identify-confirmation` |
| 주민등록등본 | 주민등록등본 교부 | `/v1/kr/public/mw/resident-registration-copy/issuance` |
| 장애인증명서 | 장애인 증명서 | `/v1/kr/public/mw/certificate/disability` |

- 인증 흐름: 1차 요청 → `CF-03002` → 휴대폰 인증 → `인증 완료 확인`(2차 요청 `is2Way`·`simpleAuth`·`twoWayInfo`) → 실제 응답.
- 자동 조회가 안 되는 서류(신분증 사본·수급자 증명서 등)는 **직접 준비**로 표시합니다. 복지로 수급자 증명은 CODEF에 상품이 없어 자동 조회하지 않습니다.
- 프록시는 키를 secret에만 두고, 요청마다 받은 본인확인 정보를 저장하지 않습니다. `PROXY_TOKEN`을 걸면 아무나 프록시를 쓰지 못합니다.

## 5. 파일과 배포

```
index.html    # 프로토타입 전체 (배포본)
README.md     # 이 문서
CLAUDE.md     # 구조·규칙 (AI 에이전트·사람 공용)
.nojekyll
proxy/                          # 실제 기관 조회용 백엔드 프록시 (별도 배포)
  cloudflare-worker.js          #   Cloudflare Workers 단일 파일
  wrangler.toml                 #   배포 설정(환경변수 자리)
  README.md                     #   키 발급·배포·연결 3단계 안내
```

- `main` 브랜치에 push하면 GitHub Pages가 자동 반영합니다(1분 내외).
- 로컬 원본은 `prototypes/disability-job-counselor.html`이며 배포 전 `index.html`과 동일하게 맞춥니다(MD5).
- 접근성 설정은 `daon.a11y.v1`, 진행 상태는 `daon.state.v1`(스키마 v4), 프록시 주소·접속 토큰은 `daon.codef.v1`로 브라우저에만 저장됩니다. 실제 조회로 받은 값은 화면 메모리에만 있고 저장소·서버로 나가지 않습니다.
